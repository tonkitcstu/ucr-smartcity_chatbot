# 01 — Needs

## ผู้แจ้งในชุมชน (R)

### การเล่าเรื่อง

| รหัส | ความต้องการ | ระดับ |
|---|---|---|
| R1 | แจ้งปัญหาได้ทันทีเมื่อเจอ ไม่ต้องจำไว้รอให้มีคนมาถาม (ช่องทางหลักของระบบ) | Must |
| R2 | เล่าด้วยภาษาของตัวเอง ไม่ต้องเลือกหมวดหมู่หรือกรอกฟอร์ม | Must |
| R3 | เล่าในรูปแบบที่ตัวเองถนัด (ดูตารางด้านล่าง) | ตามตาราง |
| R4 | บอกตำแหน่งที่เกิดปัญหาได้ง่ายด้วยการปักหมุด แม้ไม่รู้พิกัด | Must |
| R5 | พิมพ์บอกสถานที่ (เช่น "หน้าวัดสุทธิ") แทนการปักหมุดได้ | Could |
| R6 | เล่าเพิ่มหรือแก้เรื่องที่เคยเล่าได้ เช่น ส่งรูปตามมาทีหลัง โดยไม่ถูกนับเป็นเรื่องใหม่ | Should |
| R7 | ไม่ต้องเล่าข้อมูลส่วนตัวซ้ำ ระบบจดจำสิ่งที่เคยบอกไว้ เช่น ชื่อ อายุ ส่วนที่อยู่จะจดจำเฉพาะเมื่อผู้แจ้งบอกให้จำ และระบบจะไม่ถามข้อมูลที่ผู้แจ้งไม่เคยบอก | Should |
| R8 | ไม่ต้องเรียนรู้เครื่องมือใหม่ และเล่าจบได้ในไม่กี่นาที | Should |

**R3 — ประเภทข้อมูลที่ส่งผ่าน LINE ได้**

| ประเภท | ระดับ |
|---|---|
| ข้อความ | Must |
| รูปภาพ | Must |
| ตำแหน่ง (location) | Must (ดู R4) |
| ข้อความเสียง | Should |
| สติกเกอร์ | Should |
| วิดีโอ | Won't |

### ระหว่างคุย

| รหัส | ความต้องการ | ระดับ |
|---|---|---|
| R9 | รู้ระหว่างคุยว่าเรื่องที่เล่าถูกบันทึกแล้ว (ไม่มีการแจ้งผลกลับภายหลัง) | Should |
| R10 | รู้ว่าระบบสนใจเรื่องแบบไหน และไม่รู้สึกถูกปฏิเสธเมื่อเล่าเรื่องนอกขอบเขต | Should |
| R11 | ถ้าเป็นเหตุด่วนหรืออันตรายต่อชีวิต ได้รู้ทันทีว่าควรติดต่อที่ไหน เช่น 1669, 199 — ระบบไม่ใช่ศูนย์ช่วยเหลือ แต่ต้องไม่เพิกเฉย | Must |
| R12 | ถ้าระบบขัดข้อง ไม่ถูกปล่อยให้เงียบ และเรื่องที่เล่าไปแล้วไม่หาย | Must |

### ข้อมูลส่วนตัว

| รหัส | ความต้องการ | ระดับ |
|---|---|---|
| R13 | รู้ก่อนให้ข้อมูลว่าระบบเก็บอะไรบ้าง (เรื่อง ตำแหน่ง รูป และข้อมูลส่วนตัวที่จดจำไว้) ส่งให้ใคร และใช้ทำอะไร (PDPA) | Must |
| R14 | เรื่องที่เล่าไม่ถูกเปิดให้คนอื่นในชุมชนเห็น | Must |
| R15 | ไม่ถูกรบกวนด้วยข้อความซ้ำ ๆ และขอหยุดรับข้อความที่ไม่ได้ทักไปเองได้ | Must |
| R16 | ขอลบเรื่องและข้อมูลของตัวเองได้ รวมถึงสิ่งที่ระบบจดจำไว้ (PDPA) | Must |

### ไว้ทีหลัง

| รหัส | ความต้องการ | ระดับ |
|---|---|---|
| R17 | เห็นภาพรวมปัญหาในชุมชนของตัวเอง (ภาพรวม ไม่ใช่รายคน) | Won't |

## ทีมออกแบบเมือง (D)

เรียกใช้ข้อมูลผ่าน API จากระบบของตัวเอง แผนที่อยู่ฝั่งทีมออกแบบ ไม่ใช่ฝั่งเรา

### เนื้อหารายงาน

| รหัส | ความต้องการ | ระดับ |
|---|---|---|
| D1 | **รู้ผลกระทบที่เกิดกับชาวบ้านโดยตรง ในพื้นที่ที่เจ้าหน้าที่เข้าไม่ถึง** เช่น ในบ้าน หลังบ้าน พื้นที่ส่วนบุคคล (คุณค่าหลักของระบบ) | Must |
| D2 | ได้เฉพาะปัญหาเชิงพื้นที่ ไม่มีเรื่องพิพาทระหว่างคนปนมา ¹ | Must |
| D3 | ได้สรุปพร้อมป้ายประเภทเรื่อง (tag) ก่อน โดยสรุปไม่มีคำหยาบหรือชื่อบุคคลอื่น และเปิดดูเรื่องฉบับเต็ม (คำพูดจริงของผู้แจ้ง) ได้เมื่อต้องการ | Must |
| D4 | ได้ตำแหน่ง (geometry) ที่นำไปใช้ได้เมื่อผู้แจ้งให้มา ถ้าไม่ให้ ก็ยังได้รายงานโดยไม่มีตำแหน่ง | Must |
| D5 | ได้ไฟล์แนบ เช่น รูปภาพ ที่ผู้แจ้งส่งมาประกอบเรื่อง | Must |
| D6 | รู้ว่าผู้แจ้งเป็นคนกลุ่มไหน (ช่วงอายุ หมู่บ้าน) จากสิ่งที่ผู้แจ้งเล่าเอง | Should |
| D7 | ไม่ได้รับชื่อหรือ LINE ID ของผู้แจ้ง | Must |
| D8 | ได้เรื่องเข้ามาสม่ำเสมอ แม้ผู้แจ้งจะไม่นึกถึงระบบเอง (ช่องทางเสริมของ R1) | Should |

¹ เกณฑ์: **แก้ได้ด้วยการออกแบบพื้นที่หรือไม่** — ระบบเป็นผู้ตัดสิน ไม่ใช่ภาระของผู้แจ้ง
เช่น น้ำท่วมทุกครั้งที่ฝนตก, แดดส่องเข้าบ้าน, กลิ่นจากโรงงานหรือคลองเน่า = อยู่ในขอบเขต
แต่กลิ่นทำอาหารจากบ้านข้าง ๆ = เรื่องระหว่างคน ไม่อยู่ในขอบเขต

### การรับข้อมูล

| รหัส | ความต้องการ | ระดับ |
|---|---|---|
| D9 | ดึงเฉพาะรายงานที่เพิ่ม แก้ไข หรือถูกลบ นับจากครั้งล่าสุดได้ | Should |
| D10 | รูปแบบข้อมูลคงที่ ถ้าจะเปลี่ยนต้องแจ้งล่วงหน้า | Should |
| D11 | มีแค่ระบบของทีมออกแบบที่เข้าถึงข้อมูลได้ | Must |
| D12 | รู้ได้ตลอดว่าตอนนี้มีป้ายประเภทเรื่อง (tag) อะไรบ้าง | Should |

## ทีมพัฒนา (T)

| รหัส | ความต้องการ | ระดับ |
|---|---|---|
| T1 | ตรวจย้อนหลังได้ว่าระบบตอบแบบนั้นเพราะอะไร โดยเห็นทั้งบทสนทนาและข้อมูลที่ส่งให้ AI | Must |
| T2 | รู้ทันทีเมื่อระบบไม่ตอบหรือขัดข้อง ไม่ต้องรอผู้ใช้แจ้ง | Should |
| T3 | เปลี่ยนผู้ให้บริการ AI ได้โดยไม่ต้องแก้ทั้งระบบ | Must |
| T4 | รู้ปริมาณ token และโควตาที่ใช้ในแต่ละบทสนทนา | Should |
| T5 | รันระบบทั้งหมดบนเครื่องตัวเองได้ | Must |
| T6 | แก้โค้ดได้อย่างมั่นใจ มีชุดทดสอบคอยจับเมื่อมีอะไรพัง | Must |
| T7 | ทดสอบพฤติกรรม AI ซ้ำได้ และวัดได้ว่าแก้ prompt แล้วดีขึ้นหรือแย่ลง | Could |
| T8 | อ่านและเข้าใจโค้ดได้ทั้งหมด ไม่หลุดการควบคุม | Must |
| T9 | นักพัฒนาใหม่ติดตั้งและเข้าใจระบบได้จากเอกสาร โดยไม่ต้องถามคนเดิม | Should (Must ก่อนส่งมอบ) |
| T10 | ค่าใช้จ่าย AI ไม่พุ่งเกินเพดาน แม้มีคนส่งข้อความรัว ๆ หรือก่อกวน | Must |

## ผู้ดูแลระบบ (A)

| รหัส | ความต้องการ | ระดับ |
|---|---|---|
| A1 | เห็นว่ามีรายงานเกิดขึ้นที่ไหนบ้างบนแผนที่ (ใช้ทดสอบและปรับแต่งระหว่างพัฒนา ระยะยาวอาจให้ทีมออกแบบดูแลแทน) | Should |
| A2 | รู้ว่าบอทยังทำงานปกติหรือล่มอยู่ | Must |
| A3 | ดูรายการรายงานทั้งหมด และกรองตามช่วงวันที่ได้ | Must |
| A4 | มีแค่แอดมินที่เข้าถึงหน้าจัดการได้ โดยต้องยืนยันตัวตนก่อน | Must |
| A5 | คำขอลบข้อมูลจากผู้แจ้งส่งมาถึงแอดมินเองโดยไม่ตกหล่น และแอดมินยืนยันลบได้ครบทุกส่วน รวมถึงสิ่งที่ระบบจดจำไว้ | Must |
| A6 | เลือกได้ว่าจะให้ระบบส่งข้อความชวนคุยแบบอัตโนมัติหรือไม่ | Could |
| A7 | ส่งข้อความหาชุมชนเองได้ | Could |
| A8 | ให้และเพิกถอนสิทธิ์เข้าถึง API ของทีมออกแบบได้ | Could |
| A9 | คนรับช่วงทำ A1–A8 ได้ โดยไม่ต้องรู้โค้ดและไม่ต้องถามคนเดิม | Should (Must ก่อนส่งมอบ) |
