# 02 — Constraints

ข้อจำกัดคือกรอบที่เราเลือกเองไม่ได้ หรือตัดสินไปแล้วว่าจะไม่เปลี่ยน แต่ละข้อบอกไว้ว่ากระทบ need ข้อไหน

## ธุรกิจ (BC)

| รหัส | ข้อจำกัด | เพราะอะไร | กระทบ need |
|---|---|---|---|
| BC1 | มีนักพัฒนาคนเดียว | คนมีจำกัด | ทุกข้อ — ทำข้อ Must ก่อนเสมอ |
| BC2 | ข้อความที่บอททักไปหาคนก่อน ต้องจำกัดจำนวนต่อคน และคนรับต้องขอหยุดรับได้ | ไม่อยากให้ชาวบ้านรำคาญ และ LINE คิดโควตาข้อความแบบนี้ (ข้อความที่ตอบตอนเขาทักมาเองไม่นับโควตา) — ดู AS5 | R15 (ไม่ถูกรบกวน ขอหยุดรับได้), D8 (เรื่องเข้ามาสม่ำเสมอ), A6 (เปิด/ปิดข้อความชวนคุย), A7 (แอดมินส่งข้อความเอง) |

## เทคนิค (TC)

| รหัส | ข้อจำกัด | เพราะอะไร | กระทบ need |
|---|---|---|---|
| TC1 | ชาวบ้านใช้งานผ่าน LINE OA ช่องทางเดียว | ขอบเขตของโปรเจกต์ | R1 (แจ้งได้ทันที), R3 (ส่งข้อมูลแบบที่ LINE รองรับ), R8 (ไม่ต้องเรียนรู้เครื่องมือใหม่) |
| TC2 | ใช้ Python 3.12, FastAPI, PostgreSQL, Redis, LINE Messaging API และ OpenAI SDK (ใช้เรียก AI) จัดการแพ็กเกจด้วย uv | เป็นเครื่องมือที่ Idea ใช้เป็นและอ่านเข้าใจ | T5 (รันบนเครื่องได้), T8 (เข้าใจโค้ดทั้งหมด) |
| TC3 | ใช้ฐานข้อมูลใหม่ชื่อ `ucr_chatbot_ai` ห้ามเขียนลงฐานเดิม `ucr_v3` | ฐานเดิมมีข้อมูลจริงอยู่ และชื่อตารางซ้ำกัน | — |
| TC4 | API เดิมที่ทีมออกแบบเรียกอยู่ (`/api/dashboard/*`) ต้องยังใช้ได้มากที่สุดเท่าที่ทำได้ โดยดึงข้อมูลจากฐานใหม่แล้วแปลงหน้าตาให้เหมือนเดิม และต้อง (1) ไม่ส่ง LINE ID จริงออกไป ส่งรหัสผู้ใช้ของบอทเองแทน (2) ตรวจสิทธิ์แบบเดิม คือใช้ JWT ที่ใช้รหัสลับ (`SECRET_KEY`) ร่วมกับระบบทีมออกแบบ | ระบบของทีมออกแบบเรียกใช้อยู่ จะพังไม่ได้ | D7 (ไม่ได้ชื่อหรือ LINE ID ของผู้แจ้ง), D10 (หน้าตาข้อมูลคงที่ ต้องบอกก่อนเปลี่ยน), D11 (เฉพาะระบบทีมออกแบบเข้าถึงได้) |
| TC5 | เรียก AI ผ่านรูปแบบมาตรฐานของ OpenAI ตัวจริงใช้ Gemini ส่วนตอนพัฒนาใช้ AI ค่ายไหนก็ได้ (ตอนนี้ Typhoon) — ผลที่ได้ตอนพัฒนาอาจไม่เหมือนตัวจริง | ประหยัดค่าใช้จ่าย และเปลี่ยนค่ายได้ | T3 (เปลี่ยนผู้ให้บริการ AI ได้), T7 (ทดสอบพฤติกรรม AI ซ้ำได้) |
| TC6 | Gemini แบบฟรีใช้ได้น้อยมากต่อวัน (รุ่น flash ประมาณ 20 ครั้งต่อวัน เลยใช้รุ่น flash-lite แทน) | เงื่อนไขของ Google | T4 (รู้ว่าใช้โควตาไปเท่าไหร่), T10 (ค่า AI ไม่เกินเพดาน), R12 (ระบบขัดข้องไม่เงียบ) |
| TC7 | ข้อความที่ส่งถึงชาวบ้าน AI เป็นคนเขียนเสมอ ห้ามเขียนข้อความหรือปุ่มตอบใช่/ไม่ใช่ตายตัวไว้ในโค้ด **ยกเว้น 3 กรณี**: (1) ข้อความสำรองตอน AI ล่มหรือโควตาหมด (2) ข้อความที่แอดมินพิมพ์เอง (3) การ์ดแจ้ง PDPA ที่มีปุ่มกดยอมรับ ซึ่งต้องใช้ถ้อยคำเดิมทุกครั้งตามที่ผ่านการตรวจ (LC3) | หลักของโปรเจกต์ (CLAUDE.md) | R2 (เล่าด้วยภาษาตัวเอง ไม่มีฟอร์ม), R12 (ระบบขัดข้องไม่เงียบ), R13 (รู้ก่อนให้ข้อมูล), A7 (แอดมินส่งข้อความเอง) |
| TC8 | ตัวจริงรันบน EC2 ด้วย Docker ส่วนตอนพัฒนารันบนเครื่องตัวเอง แล้วต่อเข้า LINE ผ่าน ngrok | เป็นเครื่องที่แล็บมีอยู่ | T5 (รันบนเครื่องได้), T2 (รู้เมื่อระบบล่ม) |
| TC9 | LINE มีเรื่องเวลาที่ต้องระวัง 2 อย่าง: (1) ถ้าจะตอบแบบไม่เสียโควตา ต้องตอบภายใน **1 นาที** หลังชาวบ้านส่งข้อความ จึงต้องตั้งเวลารอ AI ให้น้อยกว่า 1 นาที ถ้า AI ไม่ตอบทันเวลา ให้ส่งข้อความสำรองภายในนาทีนั้นเลย (2) รูปและเสียงที่ชาวบ้านส่งมา LINE จะลบทิ้งเองหลังผ่านไปสักพัก (ไม่บอกว่านานแค่ไหน) ต้องดาวน์โหลดมาเก็บทันทีที่ได้รับ | ข้อกำหนดของ LINE | R12 (ระบบขัดข้องไม่เงียบ), D5 (ได้ไฟล์แนบ), BC2 (โควตาข้อความ) |
| TC10 | LINE OA หนึ่งช่องส่งข้อความเข้าได้แค่ระบบเดียว: (1) ตอนพัฒนาต้องใช้ช่องทดสอบแยกจากช่องจริง ไม่อย่างนั้นข้อความของชาวบ้านจะวิ่งเข้าเครื่องเรา (2) วันที่ย้ายมาใช้ระบบใหม่ ระบบเก่าบน `main` จะหยุดรับข้อความทันที เปิดคู่กันไม่ได้ (3) ถ้าที่อยู่ของ API เดิมเปลี่ยน ต้องบอกทีมออกแบบล่วงหน้า | ข้อกำหนดของ LINE (ตั้งปลายทางรับข้อความได้ที่เดียว) | R12 (ระบบขัดข้องไม่เงียบ), D10 (ต้องบอกก่อนเปลี่ยน) |

## กฎหมาย (LC)

| รหัส | ข้อจำกัด | เพราะอะไร | กระทบ need |
|---|---|---|---|
| LC1 | ก่อนเก็บข้อมูล ต้องบอกให้ครบว่าเก็บอะไร ส่งให้ใคร เอาไปใช้ทำอะไร แล้วให้ชาวบ้านกดยอมรับก่อน โดยส่งเป็นการ์ด (Flex message) ให้อ่านแล้วกดปุ่ม ถามแค่ครั้งแรกที่ใช้งาน ข้อความที่ส่งมาก่อนกดยอมรับ **ไม่เก็บ และไม่ส่งให้ AI** (เก็บแค่ว่าคนนี้กดยอมรับแล้วหรือยัง) การ์ดจึงต้องมีเบอร์ฉุกเฉิน 1669 และ 199 และบอกให้เล่าใหม่หลังกดยอมรับ | PDPA | R13 (รู้ก่อนให้ข้อมูล), R11 (เหตุด่วนรู้ทันทีว่าติดต่อที่ไหน), R1 (แจ้งได้ทันที) |
| LC2 | ชาวบ้านขอลบข้อมูลได้ **ส่วนที่เราลบได้ต้องลบให้หมด**: ข้อมูลในฐาน ไฟล์แนบ สิ่งที่บอทจำไว้ และบันทึกบทสนทนากับข้อมูลที่ส่งให้ AI (T1) แล้วแจ้งทีมออกแบบให้ลบตาม (ดู AS4) **ส่วนที่เราลบไม่ได้**: ประวัติแชตในแอป LINE และข้อมูลที่ Google เก็บไว้ (LC4) ต้องบอกเรื่องนี้ไว้ในการ์ด PDPA | PDPA | R16 (ขอลบข้อมูลตัวเองได้), A5 (แอดมินยืนยันลบครบ), T1 (ตรวจย้อนหลังได้) |
| LC3 | ถ้อยคำในการ์ด PDPA ต้องให้แล็บหรือฝ่ายกฎหมายตรวจก่อนเปิดใช้จริง | PDPA | R13 (รู้ก่อนให้ข้อมูล) |
| LC4 | ถ้าใช้ Gemini แบบฟรี Google เอาข้อความที่เราส่งไปใช้พัฒนาบริการของเขาได้ และพนักงาน Google อาจอ่านด้วย (ข้อยกเว้นมีแค่ยุโรป ไม่รวมไทย) ก่อนเปิดใช้จริงจึงต้องเปลี่ยนเป็นแบบเสียเงิน ถ้ายังเปลี่ยนไม่ได้ ต้องบอกเรื่องนี้ในการ์ด PDPA | เงื่อนไขของ Google | R13 (รู้ว่าข้อมูลส่งให้ใคร), AS1 (งบค่า AI) |

## สมมติฐาน (ยังไม่รู้แน่ ถือแบบนี้ไปก่อน)

| รหัส | ถือว่า | กลับมาดูอีกครั้งเมื่อ |
|---|---|---|
| AS1 | ยังไม่มีงบค่า AI ที่ชัดเจน ใช้แบบฟรีไปก่อน แล้วจดตัวเลขการใช้จริงไว้ (T4) อนาคตอาจเปลี่ยนเป็นจ่ายตามที่ใช้ แล้วแต่อาจารย์ | ก่อนเปิดให้ชาวบ้านใช้จริง ต้องได้ตัวเลขเพดานของ T10 (ค่า AI ไม่เกินเพดาน) |
| AS2 | เราเป็นคนกำหนดหน้าตาข้อมูลของ API ใหม่เอง ทีมอื่นค่อยมาขอเปลี่ยนหรือเพิ่มทีหลัง | เมื่อมีทีมขอเปลี่ยน — ต้องบอกล่วงหน้าตาม D10 |
| AS3 | จะส่งมอบให้คนที่ไม่ใช่นักพัฒนาดูแลต่อ | เมื่อแล็บยืนยันแผนส่งมอบ — กระทบ T9 (เอกสารสำหรับคนรับช่วง), A9 (คนรับช่วงทำงานแอดมินได้) |
| AS4 | ทีมออกแบบจะลบข้อมูลตามเมื่อเราแจ้ง (ยังไม่มีข้อตกลงเป็นลายลักษณ์อักษร) | ก่อนเปิดใช้จริง — ถ้าไม่มีข้อตกลง LC2 จะทำได้ไม่ครบ |
| AS5 | ใช้ LINE OA แพ็กเกจฟรีไปก่อน (จากบล็อกภายนอก ได้ประมาณ 200–300 ข้อความทักหาต่อเดือน ส่งหาเพื่อน 200 คนครั้งเดียวก็หมด) | เมื่ออาจารย์ตัดสินว่าจะอัปแพ็กเกจไหม — แล้วค่อยตั้งเพดานของ BC2 |
