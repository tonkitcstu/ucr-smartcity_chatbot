# 03 — User Stories

ทุก story อ้าง need ที่รองรับ ระดับ (MoSCoW) ใช้ตาม need หลักของ story (ข้อแรกในคอลัมน์ need) ข้อที่ตามมาคือ need หรือข้อจำกัดที่ story ต้องเคารพ
ตัวเลขที่ยังไม่รู้ (เพดาน โควตา) เขียนเป็น N แล้วบอกว่ารอสมมติฐานข้อไหน

## เส้นทางหลัก (happy path) — ผู้แจ้งเล่าเรื่อง → รายงาน → ทีมออกแบบดึงไปใช้

|---|---|---|---|---|---|---|
| S1 | Must | ผู้แจ้งในชุมชน | พอเพิ่มเพื่อนบอท ได้อ่านว่าระบบเก็บอะไร ส่งให้ใคร แล้วกดยอมรับก่อนเล่า | ฉันรู้ก่อนว่าเรื่องของฉันจะไปอยู่ที่ไหน | R13 (รู้ก่อนให้ข้อมูล), R11 (เหตุด่วนรู้ว่าติดต่อที่ไหน), LC1 (การ์ด PDPA กดยอมรับ) | **Given** ยังไม่เคยกดยอมรับ **When** เพิ่มเพื่อนบอท **Then** ได้การ์ด PDPA ทันที ที่มีปุ่มยอมรับ เบอร์ 1669 กับ 199 และบอกให้เล่าใหม่หลังกดยอมรับ<br>**Then** การ์ดบอกครบว่าเก็บอะไร (เรื่อง ตำแหน่ง รูป ข้อมูลส่วนตัวที่จดจำ) ส่งให้ใคร (ทีมออกแบบเมือง ผู้ให้บริการ AI) ใช้ทำอะไร และส่วนที่ลบไม่ได้ (ประวัติแชตในแอป LINE และข้อมูลที่ Google เก็บถ้ายังใช้ Gemini แบบฟรี — LC2, LC4)<br>**Then** ถ้อยคำในการ์ดผ่านการตรวจของแล็บหรือฝ่ายกฎหมายก่อนเปิดใช้จริง (LC3)<br>**Given** ยังไม่กดยอมรับ (รวมถึงคนที่เป็นเพื่อนอยู่ก่อนเปิดระบบใหม่ ซึ่งไม่ได้การ์ดตอนเพิ่มเพื่อน) **When** ส่งข้อความใด ๆ มา **Then** ข้อความนั้นไม่ถูกเก็บ และไม่ถูกส่งให้ AI<br>**Then** บอทส่งการ์ด PDPA ให้อีกครั้ง<br>**Given** กดยอมรับแล้ว **When** ทักครั้งต่อไป **Then** ไม่เห็นการ์ดอีก |
| S2 | Must | ผู้แจ้งในชุมชน | พิมพ์เล่าปัญหาแถวบ้านด้วยคำพูดของตัวเอง | เรื่องของฉันไปถึงทีมออกแบบ โดยไม่ต้องเลือกหมวดหรือกรอกฟอร์ม | R1 (แจ้งได้ทันที), R2 (เล่าด้วยภาษาตัวเอง), TC7 (AI แต่งข้อความเสมอ), TC9 (ตอบภายใน 1 นาที) | **Given** กดยอมรับแล้ว **When** พิมพ์ "น้ำท่วมหน้าบ้านทุกครั้งที่ฝนตก" **Then** บอทตอบภายใน 1 นาที<br>**Then** คำตอบเป็นข้อความที่ AI แต่ง ไม่มีปุ่มใช่/ไม่ใช่ตายตัว |
| S3 | Must | ผู้แจ้งในชุมชน | ส่งรูปประกอบเรื่องที่เล่าได้ | ทีมออกแบบเห็นสภาพจริง | R3 (ส่งข้อมูลแบบที่ LINE รองรับ), D5 (ได้ไฟล์แนบ), TC9 (ดาวน์โหลดทันที) | **Given** กำลังเล่าเรื่องอยู่ **When** ส่งรูป **Then** ระบบดาวน์โหลดรูปมาเก็บทันที<br>**Then** รูปผูกกับเรื่องที่กำลังเล่า ไม่กลายเป็นเรื่องใหม่ |
| S4 | Must | ผู้แจ้งในชุมชน | ปักหมุดบอกตำแหน่งที่เกิดปัญหา | ทีมออกแบบรู้ว่าปัญหาอยู่ตรงไหน แม้ฉันไม่รู้พิกัด | R4 (ปักหมุดได้ง่าย), D4 (ได้ตำแหน่งเมื่อผู้แจ้งให้มา) | **Given** กำลังเล่าเรื่องอยู่ **When** ส่งตำแหน่งผ่าน LINE **Then** รายงานมีพิกัด lat/lon<br>**Given** ผู้แจ้งไม่ส่งตำแหน่ง **When** เล่าจบ **Then** ยังได้รายงาน แค่ไม่มีพิกัด |
| S5 | Should | ผู้แจ้งในชุมชน | รู้ระหว่างคุยว่าเรื่องที่เล่าถูกบันทึกแล้ว | ฉันมั่นใจว่าเรื่องไม่หาย ไม่ต้องเล่าซ้ำ | R9 (รู้ว่าถูกบันทึกแล้ว) | **Given** เล่าเรื่องที่อยู่ในขอบเขต **When** รายงานถูกสร้าง **Then** บอทบอกในบทสนทนาว่าบันทึกแล้ว |
| S6 | Must | ผู้แจ้งในชุมชน | ถ้าระบบขัดข้อง ยังได้คำตอบ และเรื่องที่เล่าไปแล้วไม่หาย | ฉันไม่ถูกปล่อยให้รอเงียบ ๆ | R12 (ขัดข้องไม่เงียบ), TC7 ข้อยกเว้น (1) ข้อความสำรอง, TC9 (ตอบภายใน 1 นาที) | **Given** AI ล่ม ช้าเกินเวลา หรือโควตาหมด **When** ผู้แจ้งส่งข้อความ **Then** ได้ข้อความสำรองภายใน 1 นาที<br>**Then** ข้อความที่ส่งมาถูกเก็บไว้ ไม่หาย<br>**Given** มีข้อความค้างจากตอนขัดข้อง **When** AI กลับมาใช้ได้ **Then** ข้อความที่ค้างถูกนำไปทำต่อ และกลายเป็นรายงานได้ตามปกติ โดยผู้แจ้งไม่ต้องเล่าซ้ำ |
| S7 | Must | ทีมออกแบบเมือง | ได้รายงานที่มีสรุปสั้นพร้อมป้ายประเภทเรื่อง (tag) และเปิดดูคำพูดเต็มของผู้แจ้งได้ | ฉันเห็นผลกระทบที่เกิดกับชาวบ้านจริง โดยไม่ต้องอ่านแชตทั้งหมด | D1 (รู้ผลกระทบกับชาวบ้านโดยตรง), D2 (เฉพาะปัญหาเชิงพื้นที่), D3 (สรุป + tag + เรื่องฉบับเต็ม) | **Given** ผู้แจ้งเล่าเรื่องน้ำท่วม **When** รายงานถูกสร้าง **Then** มีสรุป มี tag และมีคำพูดเต็มของผู้แจ้ง<br>**Then** สรุปไม่มีคำหยาบและไม่มีชื่อบุคคลอื่น<br>**Given** เป็นเรื่องพิพาทระหว่างคน **When** เล่าจบ **Then** ไม่เกิดรายงาน |
| S8 | Must | ทีมออกแบบเมือง | ดึงรายงานผ่าน API เดิม (`/api/dashboard/*`) ได้เหมือนเดิม | ระบบของเราไม่พังตอนบอทย้ายไประบบใหม่ | D7 (ไม่ได้ชื่อหรือ LINE ID), D10 (รูปแบบข้อมูลคงที่), D11 (เฉพาะทีมออกแบบเข้าถึงได้), TC4 (API เดิมยังใช้ได้มากที่สุด) | **Given** มี JWT ที่ใช้ `SECRET_KEY` ร่วมกัน **When** เรียก `/api/dashboard/reports` **Then** ได้รายงานจากฐานใหม่ในหน้าตาแบบเดิม<br>**Then** ช่องผู้แจ้งเป็นรหัสผู้ใช้ของบอท ไม่ใช่ LINE ID<br>**Given** รายงานมีรูป **When** เรียก `/api/dashboard/image/{id}` ด้วย JWT ที่ถูกต้อง **Then** ได้ไฟล์รูปนั้น<br>**When** เรียกเส้นเดิมที่เหลือ (`/stats`, `/available-dates`, `/reports/{id}`, `/incomplete-reports`, `/form-reports`) **Then** ทุกเส้นยังตอบได้ ไม่มีเส้นไหนหายไป (เส้นที่ไม่มีข้อมูลคู่กันในระบบใหม่ส่งรายการว่าง)<br>**Given** ไม่มี JWT หรือ JWT ผิด **When** เรียก API **Then** ถูกปฏิเสธ |
